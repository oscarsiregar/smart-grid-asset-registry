# Quickstart: validating the asset explorer end to end

**Feature**: [spec.md](spec.md) · **API**: [contracts/assets-api.md](contracts/assets-api.md) ·
**UI**: [contracts/ui-asset-explorer.md](contracts/ui-asset-explorer.md)

## Prerequisites

As in feature 001 ([../001-csv-import/quickstart.md](../001-csv-import/quickstart.md)): Docker with Compose v2;
for checks outside containers Go 1.26, golangci-lint v2.13, Node 24 + pnpm 11. Sample file:
`backend/domain/assetimport/testdata/grid_assets.csv`.

## 1. Start from an empty registry, then import the sample

```sh
docker compose down -v && docker compose up --build
curl -s -F file=@backend/domain/assetimport/testdata/grid_assets.csv localhost:8080/api/imports   # 201, COMMITTED, 205
```

## 2. Automated checks (Definition of Done)

```sh
docker compose --profile test run --rm backend-test     # make check incl. integration tests
docker compose --profile test run --rm frontend-test    # pnpm test
# plus, locally: make lint (backend/), pnpm lint && pnpm build (frontend/)
```

Expected: exit code 0 everywhere.

## 3. API scenarios

| # | Command | Expected |
|---|---|---|
| A | `curl -s localhost:8080/api/assets` on an **empty** registry (before step 1's import) | `200`, `items: []`, `totalItems: 0` |
| B | `curl -s localhost:8080/api/assets` | `200`, 13 substations: `SS-001` … `SS-012`, then `SS-T01`; each with `childCount > 0` |
| C | `curl -s 'localhost:8080/api/assets?parentAssetId=SS-001'` | `200`, 5 items: 2 transformers, then 1 LV board, then 2 switchboards, each group by asset ID |
| D | `curl -s localhost:8080/api/assets/SS-001` | `200`, `path` = [SS-001], 5 `children`, `descendantCounts` = transformers 2, lvBoards 1, switchboards 2, switchboardPanels 10 |
| E | `curl -s localhost:8080/api/assets/PNL-001-1-01` | `200`, `path` = SS-001 → SWB-001-1 → PNL-001-1-01, `children: []`, `descendantCounts: null`, `ratingKva: null`, `commissionedDate: "2010-09-11"` |
| F | `curl -s localhost:8080/api/assets/ss-001` and `…/api/assets/NOPE` | `404`, `data.errorCode ASSET_NOT_FOUND` |
| G | `curl -s 'localhost:8080/api/assets?parentAssetId=NOPE'` | `404 ASSET_NOT_FOUND` |
| H | import a 2-row CSV with substation `SS/9 A` and a transformer under it, then `curl -s localhost:8080/api/assets/SS%2F9%20A` | `200`, `asset.assetId "SS/9 A"`, one child |
| I | `curl -s localhost:8080/api/assets/%zz` | `400 INVALID_REQUEST` |
| J | for every substation, compare `descendantCounts` with the counts from walking `?parentAssetId=` down the tree | equal for all 13 (SC-002; automated in the integration test) |

Note: the template rate limiter counts non-2xx responses (20 per 15 minutes); F, G and I add four.

## 4. UI scenarios (http://localhost:3000)

1. Empty registry (`down -v`, up): `/assets` shows "No assets have been imported yet." and **Import CSV**; no tree.
2. Import the sample through the panel; after "Committed — 205 assets saved", close the panel: the tree shows the
   13 substations without a reload (FR-026).
3. Expand `SS-001`: its children appear grouped transformers → LV boards → switchboards; `TX-001-2` and
   `LVB-001-1` show "Maintenance", `SWB-001-1` shows "Out of service", in-service nodes show no label.
4. Select `SS-001`: details with the three groups and counts 2 / 1 / 2 / 10; select `SWB-001-1` from the
   Switchboards group: the address becomes `/assets/SWB-001-1`, its panels are listed.
5. Select panel `PNL-001-1-01`: path `SS-001 › SWB-001-1 › PNL-001-1-01`, rating "Not recorded"; click
   `SS-001` in the path: it becomes selected.
6. Refresh on `/assets/PNL-001-1-01`, and open the same address in a new tab: `SS-001` and `SWB-001-1` are
   expanded, the panel is highlighted and visible.
7. Back and Forward walk through the previous selections.
8. Open `/assets/NOPE`: "No asset with ID NOPE exists." with "Back to all assets"; the tree still works; no toast.
9. Keyboard only: Tab into the tree, use ↑ ↓ → ← Home End and Enter to reach and select a panel.
10. With an asset selected, **Import CSV** → the address keeps `/assets/<id>?panel=import`; Escape closes the panel
    and the selection is unchanged. Re-import the sample ("Nothing to commit"): the tree does not change.
11. Stop the `api` container and expand a not-yet-loaded node / select another asset: each area shows its own
    error with **Try again**; restart `api` and retry.
12. Greyscale check (DevTools → Rendering → achromatopsia): selection and statuses are readable from text and
    markers alone.

## 5. Scale check (SC-006)

Import the 50 000-row file generated by feature 001's large-file test (or let the integration test measure the
API side): the top level appears within 2 s, and expanding a substation or selecting an asset within 1 s.
